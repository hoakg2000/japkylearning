# R02 – CSP options under cacheComponents (Next 16.4 local docs)

Scope: `node_modules/next/dist/docs` (paths relative).

## Findings
- 3 documented CSP options: nonce via `proxy.ts`; static header via `next.config` `headers()` with `'unsafe-inline'`; `experimental.sri` hashes (App Router, keeps static generation). — 01-app/02-guides/content-security-policy.md:34-130, 419-540
- Nonces require dynamic rendering (nonce read from request CSP header at SSR). — same:38, 181
- "PPR is incompatible with nonce-based CSP since static shell scripts won't have access to the nonce"; all pages must be dynamic with nonces. — same:391-397
- cacheComponents makes PPR the default: static shell (HTML + RSC payload, Suspense fallbacks, `use cache` output) prerendered; request-time APIs/`connection()` stream after. — cacheComponents.md:41; 01-getting-started/08-caching.md:445-450
- Docs do not say a page calling only `connection()` skips the shell under cacheComponents.
- Proxy `matcher` is the only documented route scoping for CSP.
- No per-route disable of cacheComponents (global flag); `dynamic = 'force-dynamic'`/`force-static` must be removed; `runtime` unsupported. — migrating-to-cache-components.md:136-174
- Inline scripts: `self.__next_f.push` (RSC payload), React Suspense reveal script; user inline scripts (e.g. theme script) need nonce or unsafe-inline. SRI covers JS files only, not inline scripts. — streaming.md:582,766; content-security-policy.md:464,538
- Dev needs `'unsafe-eval'`.

## Conflicts
CSP guide (PPR incompatible with nonce) predates cacheComponents docs (PPR default); no reconciliation documented.

## Confidence
Medium.
